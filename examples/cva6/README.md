# CVA6 example build

Documentation generated by `sphinx-systemverilog` from a **real, large
SystemVerilog design**: [CVA6](https://github.com/openhwgroup/cva6), OpenHW
Group's application-class RISC-V core.

This is not part of the published doc set. It needs a ~100 MB checkout, and its
job is validation and demonstration rather than distribution. It exists because
fixtures cannot tell you whether the tool works on real RTL — and running it
against CVA6 has already found two genuine defects.

## Build it

```bash
cd examples/cva6
make fetch      # shallow-clone CVA6 + the two RTL submodules (~107 MB, once)
make html       # -> _build/html/index.html
make open       # build and open in a browser
```

Against an existing checkout, with no clone:

```bash
make html CVA6_ROOT=/path/to/cva6
```

A different core configuration (CVA6 ships ten):

```bash
make html TARGET_CFG=cv32a65x
```

With no CVA6 present the build still succeeds and renders a single page saying
so, which keeps `make html` safe to run anywhere.

## What to look at

The doc set is **browsable**: start at the root and follow the hierarchy down.
Every type name in every tree is a link to that module's documentation, so you
can walk from `cva6` to `frontend` to `ras` and read docs at each step.

| Page | What it shows |
|---|---|
| `index` | The core's top-level module and its eleven blocks, as a linked tree |
| `blocks/frontend` | Fetch and branch prediction: the subtree, where it sits, and every submodule documented |
| `blocks/decode-issue` | Decode and issue, as peer blocks |
| `blocks/execute` | Every functional unit that *this configuration* elaborated |
| `blocks/commit-control` | Commit, flush control, CSRs, performance counters |
| `blocks/caches` | The write-through cache subsystem this config selects |
| `blocks/verification` | Tracing and RVFI probes |
| `reference` | Everything else — the vendor library blocks — so every tree link resolves |

Each block page carries the same three things: the module's own documentation
(description, ports, parameters, all read from the RTL), its **subtree**, and
**where it sits** in the design.

Worth noticing:

- `blocks/execute` shows only the functional units this configuration
  elaborated, not every unit the source can produce.
- `blocks/caches` exists because an if-generate on `CVA6Cfg` selected it; a
  different configuration would document a different subsystem.
- `lzc`, on the reference page, is instantiated 50 times at six distinct
  widths. `lzc.sv` says nothing about either fact.

## What this example has taught us

Running against CVA6 found real defects that fixtures never would:

- **Struct-valued parameters rendered as a wall of digits.** CVA6 passes its
  whole configuration as one `config_pkg::cva6_cfg_t`, which elaborates to a
  17268-bit integer. Every tree line read
  `#(CVA6Cfg=17268'd228657388165965449889...)`. Fixed — parameters now display
  by type while keeping full values as identity, so distinct configurations stay
  distinct. Regression test: `tests/model/test_struct_parameters.py`.
- **Module-local typedefs are scope-qualified with `.`, not `::`.** Found the
  same way.
- **Every module was documented as "Copyright 2018 ...".** Four separate
  comment-extraction bugs, all invisible to fixtures because fixtures have no
  license headers and no `` `include `` directives: a license header contiguous
  with the description was taken as documentation; the first line of a file was
  treated as a trailing comment for a declaration that does not exist; a
  comment sitting after an `` `include `` — belonging to the *included* file —
  was adopted by the module below it; and a detached comment several blank
  lines up was still adopted. Fixed, with tests in
  `tests/model/test_comments.py`.
- **Every cross-reference in the instance tree was silently dropped from the
  HTML.** Sphinx fills an empty `rawsource` with the node's text, after which
  the writer treats the block as a code block and discards its children. The
  doctree-level test passed the whole time; the fix is covered by a test that
  asserts on rendered HTML instead.

## Known gaps this example exposes

Each is tracked in `docs/design/cva6-informed-enhancements.md`. The example is
deliberately left showing them rather than working around them.

- **`conf.py` should not need `flist.py`.** The extension cannot be pointed at a
  `.f` filelist, so this example ships its own reader — badly, and with a long
  tail of unsupported syntax. Globbing the directory instead is *not* a
  workaround: CVA6's ten mutually exclusive `*_config_pkg.sv` files make it
  silently produce a degraded hierarchy (55 instances instead of 337). This is
  `E1`, and it turns out `pyslang` already exposes slang's own filelist reader.
- **The build emits ~43 warnings, and they are our fault, not CVA6's.** All come
  from `core/cvxif_example/` — an example coprocessor that nothing instantiates,
  which slang therefore elaborates standalone with unbound `parameter type`
  defaults. There is no way to tell the extension "only elaborate `cva6`". slang
  supports `--top`; verified that it removes exactly these diagnostics *and*
  stops uninstantiated utilities appearing as design tops. This is `E1-IMPL-9`.
- **~48 docutils warnings from doc-comment text.** Real comments are not
  reStructuredText: they contain `*` in expressions, `<email>` in author lines,
  indented continuation lines, and — worst for SystemVerilog specifically —
  **backticks**, because `` `FF `` is how the language names a macro. A comment
  reading "DEPRECATED - use `FF instead" is an unterminated RST literal. There
  is no doc style that treats comment text as plain prose.
- **`config_pkg::cva6_user_cfg_t` documents no fields.** CVA6's whole
  configuration is a packed struct, and struct members are not yet documentable
  objects — which is precisely why CVA6 maintains a 107-line scraper. This is
  `E2`.

## Layout

| File | Purpose |
|---|---|
| `conf.py` | Sphinx config; locates CVA6, reads the filelist, selects the target |
| `index.rst` | The example page |
| `flist.py` | **Temporary.** Minimal `.f` reader; deleted when `E1` lands |
| `Makefile` | `fetch` / `html` / `open` / `clean` / `distclean` |
| `_cva6/` | The checkout (git-ignored) |
